# 雨课堂（yuketang.cn）探测报告

> 探测日期：2026-10-11　方式：静态分析（登录页 + 前端 bundle + 未登录接口实测），**未使用任何账号**。
> 与 docs/06（学习通）同规格：先定"登录策略与数据形态"，再决定接入方案。

## 1. 结论摘要

**可行，而且比学习通省事。** 关键差异：

| 维度 | 学习通（docs/06） | 雨课堂 |
| --- | --- | --- |
| 数据形态 | 服务端渲染 HTML，需按模板解析 | **JSON 接口**（`/v2/api/web/*`），可直接解析字段 |
| 鉴权 | Cookie（页面生成 enc 参数辅助） | **Cookie `sessionid`**（业务接口），写操作再加 `X-CSRFToken` |
| 登录 | 扫码 | 扫码 或 账号密码（带腾讯滑块验证码） |
| 反爬 | 无感 | 作业页有"automation-risk"风控弹层机制（见 §5，只读列表预计不易触发） |

接入路线与既有架构一致：真浏览器里**人工登录一次**，Cookie 持久化在 Profile；之后所有取数都在页面上下文里带 Cookie 完成，不绕过验证码。

## 2. 登录策略（实测）

### 2.1 入口与方式

- 入口 `https://www.yuketang.cn/v2/web/login` → 重定向到 `/web/?next=/v2/web/login`（一个独立的登录应用）；
- 页面提供三种方式：
  1. **账号登录**（账号/手机号 + 密码）：加载了**腾讯滑块验证码**（`turing.captcha.qcloud.com`）与 hCaptcha SDK，预计需要拖滑块；
  2. **微信或雨课堂APP扫码登录**："首次使用需先关注公众号"；
  3. 微信快捷登录（依赖微信内浏览器）。
- 对程序的含义：与南大/学习通同款交互——需要登录时弹出内嵌浏览器窗口，用户自行扫码或账号+滑块登录；**不尝试绕过任何验证码**。

### 2.2 鉴权模型（实测）

| 形态 | 例子 | 说明 |
| --- | --- | --- |
| 业务接口 | `GET /v2/api/web/*` | 未登录返回 `401 {"errcode":401002,"errmsg":"Cookie has no sessionid"}`——**纯 Cookie 会话**，浏览器天然携带 |
| 用户接口 | `GET /api/v3/user/basic-info` | 未登录返回 `{"code":50000,"msg":"UNAUTHENTICATED"}` |
| 旧接口 | `GET /v/...`（如考试预告） | 未登录返回 200 + `{"op":"web_redirect","url":"/web?next=..."}`（跳登录页） |
| CSRF | `csrftoken` Cookie | 页面脚本：写操作把 `csrftoken` 放进 `X-CSRFToken` 头；另有 `xtbz` 站点标识头。**读取不需要** |

登录相关接口（来自登录应用 bundle）：

- `GET /api/v3/user/login/app-web-pre-info` —— 二维码预信息（`pc_web_login_ewm`）；
- `POST /api/v3/user/login/app-web-login` —— 扫码确认/登录提交（`pc_web_login_confirm`）。

**程序需要做的**：把页面放进持久化 Profile，登录一次；之后用 `sessionid` 直接调业务 JSON 接口。
会话失效的判定用业务接口的 `401002` / `UNAUTHENTICATED` / `web_redirect` 三种形态。

## 3. 数据接口（2026-10-11 登录态实测确认）

### 3.1 采集链路（v1 采用）

所有请求都必须带自定义头 **`xtbz: ykt`**（实测缺它返回 `XTBZ IS REQUIRED`）；
站点自身的 axios 还会全局附带 `X-CSRFToken`（csrftoken Cookie），桥接层已自动附带。

| 数据 | 接口 | 关键参数 | 说明 |
| --- | --- | --- | --- |
| 课程列表 | `GET /v2/api/web/courses/list?identity=2` | — | `data.list[]`：`classroom_id`（班级主键）/ `name`（班级名）/ `teacher.name` / `term` / `course.university_id`、`course.platform`（拼课程页链接用） |
| 大学标识 | `GET /c27/online_courseware/course/classroom/{cid}/get_basic_info/?classroom_id={cid}` | — | 返回 `course_sign`（如 `nju-…`），**schedule 必需**；每门课 1 次请求 |
| 课程大纲 | `GET /mooc-api/v1/lms/learn/course/chapter?cid={cid}&classroom_id={cid}&term=latest` | 不需要 sign | `data.course_chapter[]`：章 → `section_leaf_list`；leaf 含 `name/id/leaf_type/node_id/score_deadline/start_time/is_score`。**leaf_type：5=考试、6=作业、0=视频**（按此过滤） |
| 学习进度 | `GET /mooc-api/v1/lms/learn/course/schedule?cid={cid}&classroom_id={cid}&sign={sign}` | **sign 必需** | `data.leaf_schedules{leafId: 数字或{status,total,done,score}}`：`status=5` 已完成；`{total,done}` 计分项；数字是视频类进度。缺 sign 返回"参数错误"（error_code 20002） |
| （备用）学生待办 | `GET /c27/online_courseware/course/classroom/{cid}/{sku}/todo_list/?client_type=web&classroom_id={cid}` | sku 必填 | 未完成待办（含考试/作业/视频的 `score_deadline` 与 `link_url`）；v1 未采用（chapter+schedule 才是含已提交的完整集合），但 `link_url` 是详情链接模板的实测来源 |

### 3.2 实测踩到的坑（写进代码注释与测试）

1. **`section_leaf_list` 两种形态混用**（真机事故）：同一个 `course_chapter` 里，
   有的章的 `section_leaf_list` 元素是"节"，leaf 在其 `leaf_list` 里；
   而作业/考试所在的章（如"未分类教学活动""L1 …"）里，`section_leaf_list` 的元素
   **直接就是 leaf**（自带 `leaf_type`）。只认一种会漏掉全部作业与考试（首轮真机 0 条），
   解析器必须两种都处理，测试夹具也同时覆盖两种形态。
2. **schedule 的 sign 参数**：来自 `get_basic_info.course_sign`；不同大学不同（南大 `nju-…`）。
   实现里每门课先取 basic_info 再取 schedule（advisor 顺序：basic_info → chapter → schedule）。
3. **未登录的三种形态**（用于会话判定）：`401002`（/v2/api）、`UNAUTHENTICATED`（/api/v3）、
   `{"op":"web_redirect"}`（旧 /v 接口）。
4. **首页考试预告** `GET /v/rain_exam/get_upcoming_exam/` 返回 `data[]`（`type`=exam/quiz、
   `classroom_id`、`id`），当前账号为空数组；v1 未使用（课程内 chapter+schedule 已覆盖考试）。

## 4. 与现有架构的契合度

- **来源**：`courses.source` 已支持多站点（加 `yuketang`）；`kind`（作业/考试）已就绪；iPad/桌面加一个来源标签即可；
- **取数**：雨课堂是 Cookie+JSON，正好复用"页面上下文发请求"的桥接模式。计划把 `WebEnginePageBridge`
  泛化成"可配置站点"（默认仍是智汇南雍，不改变现有行为），新建 `YuketangAdapter`（走 `IPageBridge`，JSON 解析），
  **不需要**像学习通那样写 HTML 解析器；
- **登录窗口**：第三个隐藏登录窗口（`www.yuketang.cn`），仅在会话失效时弹出；
- **调度**：并入同一套周期（南大 → 学习通 → 雨课堂 串行）；
- **UI**：混排 + 来源标签（"雨课堂"）+ 既有的类型胶囊（作业绿/考试紫）。

## 5. 风险与边界

1. **作业页风控弹层**：pc.js 里有 `#homework-automation-risk-challenge` 与 `/automation-risk-sampling` 路由，
   用于疑似自动化时的风险验证。本程序**只读列表、低频访问、真人登录**，预计不易触发；如触发，程序应暂停该来源并提示人工处理（届时按学习通"需要登录"同款流程实现）。
2. **sessionid 有效期未知**：失效时走统一的"需要登录"流程（弹窗扫码/账号登录）。
3. **多部署域**：雨课堂有主站 `www.yuketang.cn`、长江/黄河/荷塘等变体；本次按用户提供的**主站**接入，
   如需其它域，把域名做成配置项即可（桥接泛化后成本很低）。
4. **只读**：不提交作业、不进入考试、不做签到；频率与南大/学习通共用周期配置。
